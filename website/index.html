PROBLEM

Edtech today

Pizza fraction sims with confetti. XP bars. Daily streak counters. The kid plays for the dopamine, the math is incidental. Patrick Skinner calls this the Aesthetic Paradox. Knewton, AltSchool, Byju's all hit this rake.

Trade Mogging

The kid wants to mog the vendor. The only way to mog is the cheapest combo. The only way to find the cheapest combo is to see equivalent fractions. The math IS the dopamine loop. The off-ramp is built in. The bazaar closes.

The kid sees only the browser column. Pure-logic modules have no IO, which makes them unit-testable and replay-debuggable. The Vercel edge call is the only network round-trip, and the kid never sees its prose.

COMPONENTS

XState v5 machine

Single source of truth for game state.

Pros
replay-debuggable, exhaustive guards, UI is pure render
Cons
extra dep for a small game, learning curve

Exact Fraction module

Integer numerator + denominator, GCD-normalized, never floats.

Pros
1/3 + 1/3 + 1/3 is exactly 1, no false-fail bugs
Cons
2x code to wrap raw numbers; loud error on misuse

@dnd-kit/core touch drag

TouchSensor with 80ms delay, 8px activation distance.

Pros
iPad Safari first-class, no HTML5 drag quirks
Cons
slight learning curve over native DnD API

Vercel Edge + Claude Haiku

/api/validate scores explanation 1-5, frontend maps to scripted line.

Pros
real AI judgment, zero LLM text to kid, <$0.0003/session
Cons
requires env var; offline falls back to keyword scorer

SVG vendor art

5 animals drawn in code, shared style system (4px stroke, same eye glyph).

Pros
consistent silhouettes, zero asset weight, MOG animation works on any vendor
Cons
flat-vector look ceiling; can't compete with Pixar polish

Hand-tuned curriculum

6 customers, each maps to one atom from the knowledge tree.

Pros
every round teaches something specific, exact minimumCost
Cons
no replay value, scaling content needs procedural gen

TRADE-OFFS

Flat SVG art ceiling

Capybara and vendors are flat vector, not raster art.

Why I accept it: silhouettes stay consistent automatically; the MOG animation works on any vendor via transform; zero asset weight; version-controlled.
When it would bite: if a hiring partner wants Pixar-polish for marketing screenshots, we'd need an art swap or a separate marketing-page render.

Hand-tuned curriculum

Six fixed customers, each authored against one atom.

Why I accept it: every round teaches something specific; minimumCost is exact, not approximate.
When it would bite: kid wants to play again tomorrow — same six customers. v1.1 adds procedural generation with a unit-test gate.

Single-IP rate limit, in-memory

/api/validate caps at 60/minute per IP using a Map.

Why I accept it: enough for any demo session; no external dep.
When it would bite: real classroom of 30 kids on one school NAT would share the limit. v1.1 swap to Upstash Redis.

No persistence between sessions

Cash resets, atom mastery is not tracked.

Why I accept it: deliberate per Skinner's off-ramp principle. The kid leaves the screen.
When it would bite: parent wants progress reports. Phase 3 native app would add opt-in family digest.

COST

Per-session AI spend

Scale projection

Cost is dominated by Claude Haiku calls in `/api/validate`. A session is 6 customers with an average of 1.4 failed trades requiring a lesson + explanation submission. Each call sends ~150 input tokens and asks for ≤32 output tokens. At Haiku 4.5 list pricing this is roughly $0.0003 per session.
